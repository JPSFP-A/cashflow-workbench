Recommended Workflow

  1. Enter your name on the welcome screen — it is recorded on every action in the audit log. Click your name badge in the header to change it.
  2. On startup the app automatically loads the most recent saved month — no click needed. To switch months, pick a different entry from the Saved month dropdown; it loads immediately on selection.
  3. To process a new month: pick the month in the New month date field, upload the AP invoice/payment report and the two cashbook text exports (180 and 132 formats), then click ▶ Process & Save. The status bar shows each stage: parsing → rule application → record count → save progress. Raw source text and processed records are stored in Supabase.
  4. The Outflow Validation tab opens first. Review AP outflows by base case row and by category, and the cashbook summary side-by-side.
  5. Switch to Map Exceptions to see unmapped lines or lines with no base case row. Click Map on any row to pre-fill the rule form. Save the rule, then click Reapply Now to rebuild immediately.
  6. Use ↻ Reapply Rules from the month panel at any time to re-run all rules against the saved source files without re-uploading.
  7. Use 📊 Multi-Month Report to compare any combination of saved months side-by-side as a base case matrix, with expandable sub-group rows. Download as Excel.
  8. Export the single-month Base Case via ⬇ Excel Report when the month is finalised.

Data Model — How Columns Work

Records from the two source files have different natural columns. The system normalises them into a shared set of fields:

AP Invoice/Payment Report (Oracle)

FieldSource columnPurpose
Base Case RowAssigned by ruleThe cashflow model reporting line (e.g. Fuel, Loan Principal, Supplier/Contractor). Top level in all summaries.
CategoryAssigned by ruleGranular rule label (e.g. JPS FUEL, Capital, Payroll). Adds detail beneath the base case row.
Pay Grouppay_group — direct from Oracle APNatural sub-grouping for AP records (FUEL, LOAN, SUPPLIER, EMPLOYEE, TAX, PURCHASE POWER…). Used as the sub-group dimension in the Multi-Month Report. No manual entry needed.
Main GroupAssigned by ruleBroadest reporting tier (Inflows, Operating Outflows, Capital Outflows, Financing, Non-Cash / Transfers).
FPCfpc — account segmentOracle function/project code. Used by FPC-based rules.
VendorvendorSupplier name. Used by vendor_contains rules.

Cashbook (JPS Ledger exports)

FieldSource columnPurpose
Base Case RowAssigned by ruleThe cashflow model reporting line (e.g. Collections, Long-term Debt Financing). Same concept as AP.
CategoryAssigned by ruleGranular label (e.g. Interest Income, F/X Gain/(Loss), Sinking Fund, Transfer).
Sub GroupAssigned by ruleSub-grouping dimension for cashbook records — replaces pay_group which is not available in the cashbook source (e.g. Collections, Treasury & F/X, Investment Income, Debt Service).
Main GroupAssigned by ruleBroadest reporting tier — same set as AP.
FPC / Cost ItemAccount segmentsUsed by cashbook_cost_range and FPC rules.
Pay GroupNot availableAlways blank for cashbook records. Sub Group is used instead.

Multi-Month sub-rows: For AP records the sub-group column in the report is the Oracle pay group (e.g. FUEL, LOAN). For cashbook records it is the sub group assigned on the rule.

Rule Form Fields

  • Condition 1 (required): The primary match — vendor name, pay group, FPC, Job #, CC, Emp #, Vendor #, description keyword, or cost item range.
  • Condition 2 / Condition 3 (optional): Additional AND conditions. All conditions must be true for the rule to match. Example: Pay group = SUPPLIER AND Job # range 1000-2000 AND Vendor contains ACME. Leave type blank to skip.
  • Category: The granular label written onto each matched record (becomes cashbook_category).
  • Base Case Row: The model reporting line the record maps to.
  • Applies to: Which source records the rule targets — AP outflows, cashbook debits, cashbook credits, or all.
  • Main Group: Broadest reporting tier. Select from the dropdown.
  • Sub Group: Cashbook rules only. AP records use pay group (from Oracle) automatically — no sub group needed on AP rules.
  • Notes: Free-text reference for the procedure or rationale.

Rule order matters — first match wins. More specific multi-condition rules must appear above broad single-condition fallbacks (e.g. RULE-0023 Supplier catch-all).

Rules

All rules are managed in the ⚙ Rules tab. Rules run in priority order (lowest number first); first match wins. Use the ▲/▼ buttons to reorder. Specific multi-condition rules must sit above broad catch-alls.

Run ↻ Reapply Rules on each saved month after adding or changing rules to apply changes to historical data.

Notes

  • Cashbook debits are the receipt side (Collections). Cashbook credits are the bank control side only and are excluded from the Base Case.
  • AP invoice/payment report is the primary source for classifying outflows.
  • Records with no base case row (transfers, bank charges) are excluded from all Base Case and Multi-Month summaries.
  • Reset / Wipe removes all records and uploads for the month. You will need to re-upload source files to reprocess after a reset.
  • No password is required. Your name from the welcome screen is stamped on every save, rule change, and audit log entry.
  • The Multi-Month Report queries the database directly — no need to have a month loaded first.
